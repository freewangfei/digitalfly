## 这两份模型是什么

### 1. 大脑：MaleCNS v1.0 连接组

雄性果蝇**完整中枢神经系统**的电镜接线图 —— 中央脑 + 视叶 + 腹神经索（相当于脊髓），
**176,422 个神经元、约 1.25 亿个突触**，约 44 人年的人工校对。

由 HHMI Janelia FlyEM、剑桥大学、MRC 分子生物学实验室与 **Google Research** 合作完成。
v1.0 发布于 2026-06-08，论文 2026-09-03 发表于 *Cell*。CC-BY 4.0。

它的关键之处在于：**这是第一次把脑和身体的神经系统放在同一张图谱上，并保留了颈部连接**
—— 也就是"大脑如何指挥身体"这条通路第一次是完整可查的。做数字果蝇需要的正是这个。

### 2. 身体：flybody

解剖学精细的成年果蝇 MuJoCo 物理模型 —— 6 条腿、翅膀、喙、触角，带流体力学。
由 **Google DeepMind × HHMI Janelia** 合作开发，*Nature* 643 (2025)。

本项目用它的 `FruitFly` 装配类按行为配置身体（行走时收翅、飞行时收腿），
不用配套的强化学习训练栈（那需要 TensorFlow/acme 一大套）。

### 3. 步态：NeuroMechFly v2 / flygym

真实果蝇行走的腿部运动学，由 NeLy-EPFL 重定向到 flybody 模型上。
只取数据文件，不引入这个包 —— 详见下文「步态用的是真实果蝇的运动学」。

## 哪些是数据，哪些是假设

这点必须说清楚，否则容易把工程近似当成生物学结论。

**直接来自数据的：**

- 神经元之间怎么连、每对连了多少个突触 —— 连接组边表
- 每个突触是兴奋还是抑制 —— 由突触前神经元的递质预测决定
  （ACh → 兴奋；GABA / 谷氨酸 / 组胺 → 抑制；其中 85,484 个神经元有实验真值）
- 谁是感觉神经元、下行神经元、运动神经元，属于哪个胸节、哪一侧 —— 官方标注字段
- 神经元动力学的形式与大部分参数 —— 取自 Shiu et al., *Nature* (2024) 在 FlyWire
  上验证过的那套泄漏积分发放模型（静息 −52 mV、阈值 −45 mV、膜时间常数 20 ms、
  不应期 2.2 ms）。其中**单突触强度必须在本数据集上重新标定**，原因见下文。

**属于工程假设的（连接组不提供，任何连接组都不提供）：**

- 运动神经元发放多少赫兹 → 肌肉出多大力。真实映射涉及神经肌肉接头、肌纤维类型、
  力-长度曲线，电镜重建里没有这些信息。
- 运动神经元 → MuJoCo 具体某个执行器的对应关系。flybody 的执行器按关节自由度建，
  和真实肌肉不是一一对应。

- 步态本身。腿怎么迈是运动学模型（来自真实果蝇录像），不是从连接组里读出来的。
  MaleCNS 有完整的腹神经索接线图，原则上中枢模式发生器应当能从中涌现，
  但那需要神经元自身的内在振荡特性（离子通道动力学），电镜重建里没有这些信息。
  flybody 官方的行走任务同样不从网络里生成步态，而是跟踪真实果蝇的参考轨迹。

所以 `bridge.py` 的做法是：**连接组决定"做什么"（速度、要不要伸喙），
运动模式发生器负责"怎么做"（关节轨迹）**。这个分工是果蝇神经系统本身的分工。

一句话：这个项目做到的是"**让真实连接组的活动去驱动一个真实的身体**"，
每一处连接组做不到的地方都在代码和本文里标了出来。

## 突触强度必须重新标定

`python cli.py calibrate`

Shiu et al. 在 FlyWire（13 万神经元、5 千万突触）上用的单突触 EPSP 是 0.275 mV。
直接搬到 MaleCNS v1.0 上会出问题：本数据集含腹神经索，18.5 万神经元、1.25 亿突触，
平均每个神经元收到约 677 个突触，是 FlyWire 的 1.8 倍。**在 0.275 mV 下，只要刺激
6 个神经元，整个网络就会进入约 48 Hz 的自持放电，撤除刺激后也停不下来** ——
癫痫样发作，不是果蝇的大脑。

标定准则是"不自持"：二分搜索出最大的、撤除刺激后活动仍能衰减到静默的突触强度。
本数据集上的临界值是 **0.0358 mV**，取 0.95 倍作为工作点 **0.0341 mV**。

准则本身不涉及任何行为学结果，不会把想要的结论标定进去 —— 味觉能不能激活伸喙，
是标定完成之后才检验的独立问题。

## 关键实验：糖味 → 伸喙

`python cli.py sim --exp sugar_pe`

![糖味实验](docs/images/sugar_pe.png)

不训练、不调参，只给连接组和 LIF 动力学，看伸喙运动神经元 **MN9** 的响应：

| 刺激对象 | 神经元数 | MN9 发放率 | 全脑平均 |
|---|---|---|---|
| 糖味通路 Sugar SEL | 6 | **16.7 Hz** | 0.06 Hz |
| 苦味通路 Bitter-SEL（阴性对照） | 4 | **0.0 Hz** | 0.00 Hz |
| 唇瓣味觉感受神经元（一级输入） | 163 | **14.2 Hz** | 0.78 Hz |
| 不给刺激（基线） | 0 | **0.0 Hz** | 0.00 Hz |

方向和真实果蝇一致：糖味驱动伸喙，苦味不驱动（苦味在真实果蝇里抑制伸喙）。
全脑活动全程保持在个位数赫兹以下，是稀疏的生理放电而不是全网爆发。

糖味 / 苦味通路的身份来自数据集 `synonyms` 字段里收录的 Yao & Scott (2022) 鉴定结果，
不是靠命名猜的。这两组神经元的递质预测都是血清素 —— 如果按"单胺类不参与快速传递"
把它们的权重置零，它们会从网络里整个消失，实验结果就全是 0。
`connectome.py` 顶部解释了为什么把单胺类按兴奋处理，以及怎么用
`--modulator-sign 0` 做对照。

## 切除实验

`python cli.py sim --exp ablation`

在真实果蝇上要用遗传学工具花几个月的功能失活实验，这里是一行代码，而且能穷举。
刺激唇瓣味觉感受神经元，读 MN9，逐个切除通路：

| 切除对象 | 神经元数 | MN9 发放率 | 相对完整网络 |
|---|---|---|---|
| （完整网络） | — | 17.5 Hz | 100% |
| 糖味通路 Sugar SEL | 6 | 70.0 Hz | **400%** |
| 苦味通路 Bitter-SEL | 4 | 46.2 Hz | 264% |
| 全部下行神经元 | 1,314 | 20.0 Hz | 114% |

切掉糖味通路，伸喙反而**增强了 4 倍**。这不是 bug：查连接组可以看到 Sugar SEL 的
1,616 个直接下游里有 549 个是抑制性的，其中 36 个直接投射到 MN9（总抑制权重 −405）。
切除它等于解除了这条前馈抑制。这类反直觉结果正是连接组仿真的用处 ——
也提醒一件事：这 6 个神经元的递质预测是血清素，它们的符号取兴奋还是取零，
会显著改变结论，用 `--modulator-sign 0` 重建可以做对照。

## 行为：行走 · 觅食 · 飞行

```bash
python cli.py behave --what walk     # 行走
python cli.py behave --what forage   # 觅食：闻着糖味走过去，够到就伸喙
python cli.py behave --what flight   # 拴系飞行
```

三种行为共用同一套结构：

```
世界/身体 ─► 感觉神经元 ─► 全脑 LIF 网络 ─► 下行神经元 ─► 指令(速度/转向)
                                                              │
                              运动模式发生器 ─► 关节轨迹 ─► MuJoCo 物理
```

### 为什么下行神经元接的是「指令」而不是关节角

这一点最初做错了，值得写下来。果蝇的行走节律不是大脑逐个关节算出来的：
腹神经索的腿部神经节含有中枢模式发生器，自己就能产生三角步态的相位关系；
大脑通过下行神经元下达的是「走快点」「向左转」这类**指令**。切断果蝇的脑，
腹神经索仍然能产生节律性腿部运动 —— 这是经典实验结果。

最初把下行神经元活动直接映射成关节目标角，果蝇当场瘫倒；改成以静息姿态为基线
做调制后能站住，但只会原地抖动。接成指令层之后才真正走起来。

### 步态用的是真实果蝇的运动学

自己按正弦拼的三角步态只能走到约 0.5 体长/秒，姿态勉强。
现在用的是 **NeuroMechFly v2 / flygym**（NeLy-EPFL）的 `single_steps_flybody.npz` ——
他们把真实果蝇在球上行走的腿部运动学重定向到了 flybody 模型上，
给出前/中/后足各一个完整步态周期的 7 个关节角轨迹和摆动相占比。

| | 速度 | 3 秒朝向漂移 |
|---|---|---|
| 自己调的正弦步态 | 0.5 体长/秒 | 大，姿态勉强 |
| **真实迈步运动学** | **2.6 体长/秒** | **2.3°（配平后）** |

真实果蝇自由行走约 1–3 体长/秒。

![行走](docs/images/walk.jpg)

```
[body] 行走配置: 执行器 65 个（翅膀收拢）, 步频 12.0 Hz
沿初始朝向前进 1.05 = 1.22 体长/秒   全脑平均 2.99 Hz   下行神经元 4.6 Hz
```

速度由下行神经元群体活动读出，会随网络活动逐渐爬升 —— 看起来就像果蝇起步加速。

**翅膀一定要收起来。** 早先的版本里翅膀被甩到远离身体的位置，看上去像掉了；
原因是把控制量写给了翅膀关节（yaw 行程可达 ±3 rad）。真实果蝇行走时翅膀折叠贴合，
对应的做法是 `use_wings=False`。

### 觅食

```
到糖源距离 2.51 -> 0.30，2.7s 时够到
MN9 伸喙峰值 200 Hz（连接组算出）
```

**哪一段是连接组做的，哪一段不是：**

- **是** — 行进速度（下行神经元活动读出）。
- **是** — 伸喙决策。口器接触到糖后，味觉输入经全脑网络传到伸喙运动神经元 MN9，
  MN9 的发放驱动口器。这条通路和 `sim --exp sugar_pe` 验证的是同一条。
- **不是** — 转向。用的是显式双侧比较趋化规则，原因见下。

### 一个阴性结果：连接组读不出「气味在左还是在右」

`python cli.py sim --exp steering`

果蝇趋化的基础是双侧比较。如果连接组 + LIF 足以支撑这个计算，那么左右嗅觉输入
不同时，下行神经元的左右活动差应当随之改变。**实测做不到：**

- 用全部 1,314 个下行神经元按解剖学左右分群，在总强度相同的条件下，
  偏左与偏右之间的读数差是 **−0.004**（动态范围约 0.03，且被总强度主导）。
- 换成功能性筛选（两次探针试验挑出差分响应最大的 40 个下行神经元），
  探针条件下对比度有 35 Hz，但气味强度稍微一改就完全失效（读数差 **+0.003**）——
  典型的过拟合，不是真实的侧别编码。

这与文献一致：Shiu et al. 证明的是连接组能复现**反射式**的感觉运动映射
（味觉→伸喙），不是精细导航计算。均一的 LIF 神经元 + 未经调节的突触权重，
不足以支撑双侧比较这种需要精确增益匹配的运算。

### 飞行（拴系）

![拴系飞行](docs/images/flight.jpg)

```
翅拍频率 218 Hz   左翅冲程幅度 0.93 rad
转向指令（左右振幅差）均值 -0.060
```

**为什么是拴系而不是自由飞行。** 自由飞行的姿态稳定需要学出来的控制器：
flybody 官方飞行任务用的是训练好的强化学习策略，权重在 figshare 上
（本机访问被对方 403 拒绝）。只靠翅膀运动学加 PD 反馈，果蝇会一边产生升力
一边翻滚 —— 试过 150 组参数，最好的一组仍然翻转。

这不是退而求其次：真实果蝇神经科学里，绝大多数飞行实验就是把果蝇固定住、
让翅膀自由拍动，用**左右振幅差**作为转向意图的读数。这里做的是同一件事，
只不过转向意图来自连接组。

升力本身是真的：翅膀用 MuJoCo 的椭球流体模型产生气动力，翅拍由 flybody 的
`WingBeatPatternGenerator` 以 218 Hz 生成，翅膀执行器是力执行器、喂的是
「目标角 − 当前角」—— 这些都按 flybody 飞行任务的配置来。

## 拧魔方

```bash
python cli.py behave --what cube --scramble 8     # A：复刻视频
```

### A · 复刻网上那批视频

![魔方从打乱到复原](docs/images/cube.jpg)

画面是**分屏**，和视频一个格式：左边任务，右边**全脑三维点云，神经元发放时闪烁**。

![分屏](docs/images/split_cube.jpg)

点云不是示意图 —— MaleCNS v1.0 的标注表里有 **141,781 个神经元的胞体三维坐标**
(`somaLocation`)，直接拿来画，按脑区着色：两侧蓝色视叶、中间橙色中央脑、
上方绿色腹神经索，白点是此刻正在发放的神经元。

![全脑点云](docs/images/brainview.jpg)

**界线标在画面上：**

| | |
|---|---|
| **连接组决定** | **什么时候拧** —— 下行神经元活动积累到阈值触发一次转动，网络越活跃拧得越快 |
| **求解器决定** | **拧哪一面** —— IDA\* 搜索出的最优解 |

实测一局（8 步打乱）：

```
打乱 8 步: D2 R2 L U2 B' R D' U2
解  8 步（IDA*，5.0s）: U2 D R' B U2 R2 L' D2
已执行 8 步，9.7s 时复原 ✓
```

网上那批视频的做法都是一样的：把连接组活动映射成操作指令，真正完成任务的是
外部程序。做 Minecraft 那个的作者自己讲得很直白 ——「这是一种探索连接组的
交互方式，不是意识的证据，也不是对活果蝇的完整重建」。区别只在于这里把
哪部分是谁干的写在了界面上。

**求解器是自己写的。** `kociemba` 和 `rubik-solver` 在本机都编译不过
（要 C 扩展和旧版构建后端），所以 `cube.py` 是一套纯 Python 实现：标准块级
状态表示 + IDA\*，剪枝表由 BFS 预算（角块朝向 3⁷、棱块朝向 2¹¹、角块排列 8!），
启发值取三者最大。8–9 步打乱一两秒内找到**最优解**，10 步要 40 秒，
超预算回退到「打乱序列的逆」。

魔方的 26 个块是 MuJoCo 的 mocap 体，每帧直接写位姿，**不参与物理仿真** ——
转动是运动学动画，不是果蝇真的推动了它。

### B · 连接组里到底有没有解魔方的信息

A 里连接组只管节奏。B 问的是更硬的问题：**把魔方局面喂进全脑网络，网络的
活动里有没有关于「该拧哪一面」的信息？**

标准的神经解码实验：300 个随机局面 → 编码成视觉神经元的发放率喂进网络 →
取 48 个读出子群的发放率作特征 → 多项逻辑回归预测正确的下一面 →
在留出集上看准确率。

```
样本 300（训练 210 / 测试 90）· 特征 48 个读出子群的发放率
解码准确率      15.6%
随机基线        16.7%
最频繁类别基线   16.7%
打乱标签对照     16.6% ± 3.7%   <- 纯过拟合能到的水平

结论：连接组的活动里能否解码出「该拧哪一面」 = False
```

**打乱标签对照是这个实验的关键**：同样的特征、打乱过的标签，重跑十次。
它给出「在这个样本量和特征维度下纯靠过拟合能到多少」。真实准确率
（15.6%）落在这个分布里面，所以网络活动里没有可用信息。

这和 `--exp steering` 的结论是一条线：连接组 + 均一 LIF 能复现**反射式**的
感觉运动映射（味觉 → 伸喙，16.7 Hz vs 0 Hz），复现不了需要精确增益匹配的
计算 —— 双侧比较不行，符号推理更不行。

魔方局面怎么喂进果蝇的脑？果蝇没有魔方感受器，所以这必然是人为约定的编码：
用一个**固定的随机投影**把块级状态映射到光感受器的发放率上。这个约定本身
不携带「该拧哪面」的信息，读不读得出来完全取决于网络。

## 感觉输入用发放率编码，不是持续电流## 感觉输入用发放率编码，不是持续电流

LIF 神经元没有适应机制，持续注入电流会让它饱和：膜电位稳态是 40 × I，
只要电流超过 0.18 mV 就会以不应期上限（约 400 Hz）发放，再加大刺激也不变。
实测把气味强度从 0.5 调到 4.0，全脑活动纹丝不动地停在 11 Hz。

所以感觉输入按 `p = 发放率 × dt` 的概率逐步门控一个阈上刺激，
让目标群体的平均发放率就等于设定值。气味只注入**对食物气味响应的嗅觉通道**
（DM1=Or42b、DM4=Or59b、DM2=Or22a、VM2=Or43b、VA2=Or92a，共 284 个），
味觉只注入 163 个唇瓣刚毛 GRN —— 真实果蝇闻到一种气味也只激活少数几类
嗅觉神经元，不是全部两千多个一起放电。

## 手写识别 —— 第一个强阳性结果

```bash
python cli.py train-vision --charset digits --reps 250   # 训练解码器
python cli.py web --port 8080                            # 用鼠标手写
```

前面几个「认知类」的探测全是阴性 —— 连接组读不出气味左右，解码不出魔方下一步。
视觉这次不一样，原因是结构性的：**这条输入走的是果蝇真正用来看东西的通路。**

### 图像怎么进到眼睛里

MaleCNS 的标注表给了 23,720 个视叶柱状神经元的**六角视柱坐标**
(`assignedOlHex1/2`)，每只眼约 **892 个视柱**。这是数据集自带的视网膜拓扑图，
所以图像是一柱一柱铺到复眼上的，不是随便投影进去的。

驱动的是 **L1 和 L2** —— 光感受器在板层的两个主要突触后靶标，对应 ON 和 OFF
通道（Joesch et al., *Nature* 2010）。光感受器本身在这套数据里没有视柱坐标：
它们的胞体在视网膜里、不在成像体积内，6,098 个中只有 28 个有坐标。
从板层这一层进是更实在的做法。

读出取的是**同一视柱里的其余神经元**（Mi1、Tm1、Tm2、T1、C3 …），排除 L1/L2 ——
读被驱动的那些等于把注入的图像原样读回来。

![视网膜映射](docs/images/retina.png)

*每对：左边是手写数字原图，右边是按 892 个六角视柱采样后重建出来的 ——
映射对了，字符的形状被忠实地采到了复眼上。*

### 结果

用**真实的 MNIST 手写数字**训练（Google GCS 镜像，9.9 MB）：

| | 准确率 |
|---|---|
| **从果蝇视觉系统解码** | **83.7%** |
| 像素基线（直接对原图做线性分类） | 84.3% |
| 打乱标签对照 | 10.9% ± 1.9% |
| 随机 | 10.0% |

**网络保留了线性可解码信息的 99%。** 离满分的差距来自线性解码器和样本量，
不是果蝇 —— 在这个训练集规模下像素基线本身也就到 88% 左右。

对比魔方（15.6% vs 打乱 16.6%）：同一个解码器、同一套流程、同一个脑。
差别完全在于刺激是不是从这只动物演化出来处理的感觉系统进去的。

### 自己画一个

Web 控制台有一块画板：用鼠标写一个数字，点**识别**，画出来的图会按 MNIST 的
规矩预处理（取包围盒 → 缩到画面的 72% → 居中），铺到双眼上，过一遍全脑网络，
再读出来。

**这件事准确地说是什么。** 是神经解码 —— 和「从猴子 V1 的群体活动解码出光栅
朝向」是同一类操作。**果蝇本身不认识数字。** 突触权重一个都没变，网络里没有
任何学习发生，学习完全发生在最外面那层线性读出上。

有个坑值得记下来：编码器的配置必须和权重存在一起。把 `probe_ms` 从 120 改成
180 之后，推理端用的特征尺度和训练时就对不上了，归一化后 logits 饱和，
每张图都返回「5」且置信 100%。现在模型文件把
`grid / layer / peak_hz / settle_ms / probe_ms` 一起钉住。

## 果蝇自己学 —— 蘑菇体的突触可塑性

```bash
python cli.py sim --exp conditioning
```

前面的手写识别，**学习发生在外挂的线性读出层**，果蝇本身没学。这一节不一样：
改的是**连接组自己的 61,210 条 KC→MBON 突触**，用的是果蝇自己的学习规则，
没有反向传播，没有外部模型。

### 回路是现成的

| | 数量 |
|---|---|
| Kenyon 细胞（稀疏编码层） | 4,064 |
| MBON（输出，决定趋近/回避） | 97 |
| 多巴胺能神经元 DAN（教学信号） | 340 |
| **KC→MBON 可塑突触** | **61,210 条，总权重 463,640** |
| 触角叶投射神经元 ALPN→KC（嗅觉输入） | 22,586 条 |

学习规则是**多巴胺门控的突触抑制**：某个区室的 DAN 发放时，那一刻活动的
Kenyon 细胞到该区室 MBON 的突触被压低（Hige et al., *Neuron* 2015；
Aso & Rubin, *eLife* 2016）。

### 结果

气味 A 与多巴胺配对训练 10 回合：

| | 惩罚区室 MBON | 对照区室 |
|---|---|---|
| 气味 A（配对）训练前 | 111.9 Hz | 84.8 Hz |
| 气味 A（配对）训练后 | **68.3 Hz** | 83.7 Hz |
| 气味 B（未配对）训练前 | 82.5 Hz | 47.3 Hz |
| 气味 B（未配对）训练后 | 88.9 Hz | 50.6 Hz |

**配对气味 −39.0%，未配对 +7.8%，特异性 5.0 倍。** 可塑突触总强度降到 93.3%。

注意效价翻转：训练前 A 的惩罚区室高于对照（111.9 vs 84.8），训练后低于对照
（68.3 vs 83.7）—— 这正是果蝇条件化后行为倾向反转的神经关联。

### 两处模型补充，必须标出来

**1. 稀疏编码是显式加的。** 真实果蝇里 APL 那个巨大的 GABA 能神经元把 KC 压到
约 5% 活跃，这是学习具有气味特异性的前提。本重建里 KC 收到的兴奋是抑制的
**7.3 倍**（184 万 vs 25 万），APL 只有 2 个神经元，压不住 64 万条 KC→KC 递归
兴奋 —— 实测任何输入都把全部 4,064 个 KC 点亮到 145 Hz。所以显式取前 5%，
替 APL 做它在真实果蝇里做的事。

**2. 稀疏化要按每个 KC 自己的基线来。** 直接取"响应最强的前 5%"选出来的是固有
输入最强的那批细胞，跟当前气味无关 —— 实测两种气味的 KC 编码重叠 **73%**，
比输入本身的重叠（25%）还高，等于网络在增加相关性。按每个 KC 的均值和标准差
归一之后重叠降到 **0%**。这对应 KC 的适应与增益控制。

学习规则本身、可塑突触的位置和数量、教学信号的通路，全部来自连接组。

### 为什么识别没法也用这个机制训练

试过了，走不通，原因是解剖学上的：**视觉进蘑菇体的通路太弱**。

- 视觉投射神经元 → Kenyon 细胞：1,616 条连接，总权重 11,094
- 触角叶投射神经元 → Kenyon 细胞：22,586 条，总权重 390,928（**35 倍**）

视觉输入只占一个 KC 总输入的 0.5%。文献里视觉是进 KCγd 亚型（腹侧副萼），
本数据里确认了：206 个 KCg-d 拿走了 8,041 的视觉权重，占其总输入 7.1%。
但即便把这批既有突触放大 25 倍，数字之间的 KC 编码分离度仍然只有 **1.02**
（1.0 = 完全分不开）—— 因为信号传到视觉投射神经元时就已经不区分数字了。

这和整个项目里反复出现的模式是一致的，值得单独写下来：

> **在标定后的工作点上，网络只能可靠传递约一个突触。** 再往下要么衰减到零，
> 要么饱和。
> 通得过的：视网膜→髓质（1 突触，85.8% 解码）· ALPN→KC（22,586 条强通路）
> · 味觉 GRN→MN9（需饱和驱动）
> 通不过的：髓质→VPN→KC（弱、多突触）· 双侧气味→下行神经元不对称



## Web 控制台

```bash
python cli.py web --port 8080 --behavior forage
```

浏览器打开后可以直接控制这只数字果蝇：

**控制**
- **行为切换** — 行走 / 觅食 / 拴系飞行 / 拧魔方，在线切换（会按行为重建
  身体配置：行走收翅、飞行收腿）
- **魔方** — 换一局（可选 4–9 步打乱）、实时看蓄力进度与「果蝇想拧哪一面」
- **分屏** — 一键开关右半屏的全脑三维点云（神经元发放时闪烁）
- **手动接管** — 速度与转向滑块 + 方向键盘；滑块拉到最左即交还给大脑
- **糖源位置** — 拖动 X / Y，果蝇会重新朝新位置走；气味可开关
- **刺激注入** — 按目标发放率（Hz）注入任意神经元群
- **神经元切除** — 一键让某条通路永久静默，看下游还剩多少响应
- **机位切换** — track1/2/3、hero、top、side、back、复眼视角
- 暂停 / 重置

**面板**
- **3D 画面** — MuJoCo 离屏渲染（NVIDIA EGL）的实时 MJPEG 流；
  `/frame` 取单帧，页面加 `?snapshot=1` 用静态帧（无头浏览器截图用）
- **脑区发放率** — 按解剖大区聚合，单色顺序色阶编码量级
- **发放率时间序列** — 全脑 / MN9 / 下行神经元，**拆成三行小倍数**：
  它们量级能差上百倍，挤在一根轴上会让其中两条读不出来，
  而加第二根 y 轴是最容易误导的画法
- **脉冲栅格图** — 全脑随机抽样神经元的滚动脉冲图
- **状态提示** — 全脑发放率超过 5 Hz 时标出「过度兴奋」，
  此时的结果不能当生理数据看

接口：`GET /api/info` · `GET /stream`（SSE 数值流）· `GET /video`（MJPEG）·
`GET /frame`（单帧）· `POST /api/control`（behavior / manual / food / odor /
stim / ablate / camera / reset / toggle）。

发放率都是在 50 ms 窗口上累计后再算的。按单步算没有意义：MN9 只有 2 个神经元，
某一步发放 1 个就会报出 1000 Hz。

仿真速度大约是实时的 0.2 倍（全脑 18.5 万神经元每步约 1.3 ms，GPU 后端），
页面上有实时倍率显示。

## 环境上的两个坑

1. **IPv6 路径是坏的。** 本机有一条经无线网卡的 IPv6 默认路由，TCP 能连上但 TLS
   握手会被中途拒绝（`SSLV3_ALERT_ILLEGAL_PARAMETER`），约一半请求瞬间失败。
   Python 的 socket 只在 TCP 层失败时才回退地址族，所以 pip/conda/requests 不会自愈。
   解决办法是 `tools/ipv4.py` —— 在进程内把 `getaddrinfo` 过滤成只返回 IPv4，
   不改动任何系统配置。curl 一律加 `-4`，`git clone` 没法强制 IPv4，所以改用
   curl 拉 tarball。

2. **GCS 单连接被限速**在 100~500 KB/s，8 路并发能聚合到 1~2 MB/s，
   所以 `download.py` 对超过 8 MB 的文件一律分片并发下载。
